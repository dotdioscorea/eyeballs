# Provider integration permissions

Checked 2 October 2026 against the six integrations in TestFlight build 8. This records published terms and unresolved authorization; it is not an Apple review decision. No integration has been removed and the queued submission has not been cancelled.

Successful login and usage requests establish technical access. They do not establish permission to distribute an app using another product’s OAuth registration or internal usage interface. Open-source licenses cover the licensed source, separately from service access and trademarks.

| Integration | Implementation | Current evidence and remaining question |
| --- | --- | --- |
| Codex | Codex public OAuth client; `backend-api/wham/usage` | OpenAI documents a supported registration flow for open-source apps using ChatGPT plans. That grant concerns eligible Responses API requests; it does not establish permission for Requota’s existing Codex client and internal quota endpoint. Confirm the appropriate registered client and usage interface. [Quickstart](https://developers.openai.com/siwc/quickstart), [registration](https://developers.openai.com/siwc/token-sharing-open-source/sign-in). |

No read-only usage-monitor exception was found. The separate permission to host the unmodified Claude Code binary does not describe Requota. Written authorization or a permitted integration is needed to resolve this incompatibility. [Authentication and credential use](https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use). |

No explicit grant for reuse of the Grok Build registration and subscription billing proxy in third-party native apps was established. Confirm the applicable developer authorization. [Consumer terms](https://x.ai/legal/terms-of-service), [enterprise terms](https://x.ai/legal/terms-of-service-enterprise). |

[CLI terms notice](https://geminicli.com/docs/resources/tos-privacy/), [OAuth policies](https://developers.google.com/identity/protocols/oauth2/policies). |

Registering a client and obtaining an appropriate quota interface remain separate questions. [API terms, section H](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service#h-api-terms), [device flow](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps#device-flow). |
| Cursor | Native PKCE browser handshake; DashboardService Connect RPC | Section 1.5 restricts extracting service data and reverse engineering. No explicit authorization for third-party quota monitors using the native handshake and dashboard RPC was established. Confirm whether this account-data use is permitted. The successful free-account test is technical evidence, not that permission. [Terms, section 1.5](https://cursor.com/terms-of-service), [CLI authentication](https://cursor.com/docs/cli/reference/authentication). |

Provider marks need a separate check. Anthropic’s legal page requires written permission for uses beyond its stated plain-text allowance; Grok’s consumer terms refer to permission and brand guidelines. The current tinted provider logos have not been approved by the providers. A source or asset being publicly downloadable does not establish trademark permission.

Apple’s [guideline 5.2.2](https://developer.apple.com/app-store/review/guidelines/#intellectual-property) requires an app’s use of third-party services to be specifically permitted under the service’s terms, with authorization available on request. Privacy metadata and demo access address different review requirements and do not resolve the restrictions above.

No provider support requests have been sent, no claim of partnership or approval has been added, and no rejection has been observed. Cline, Devin and Perplexity are not working integrations in build 8; any later implementation needs its own authorization check.
